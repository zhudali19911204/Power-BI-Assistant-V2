# Power BI Assistant V2

本地桌面版 Power BI 助手，包含 DAX 助手、Power Query 助手和基于实际查询的数据分析助手。JavaScript 界面、Python 后端、SQLite 数据库；通过配置连接部署在服务器上的大模型。当前交付为源码运行版，未打包。

## 启动

Windows 10/11，Python 3.11+（已用 Python 3.12 验证）。桌面窗口使用 Edge WebView2 Runtime；本机需安装 Power BI Desktop 才能读取和验证真实模型。

```powershell
cd "E:\AI_Project\Power BI Assistant V2"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\.venv\Scripts\python.exe desktop.py
```

依赖安装后也可双击 `start.bat`。前端采用原生 JavaScript ES Modules；运行桌面版无需 Node.js、npm 或前端构建。`package.json` 中的依赖仅用于前端开发测试。

开发预览：

```powershell
.\.venv\Scripts\python.exe desktop.py --browser --port 8765
```

默认使用自动分配的本地端口，只监听 `127.0.0.1`。关闭桌面窗口会退出对应本地服务。

## 连接服务器大模型

点击左下角“模型服务设置”，或输入框下方的模型名称，打开已保存的模型列表。点击“添加模型”，填写显示名称、API 协议、服务器 API 根地址、模型名称 / ID 和 API Key。无鉴权的内部服务可将 Key 填为 `local`。

支持保存多个模型。旧版的单模型配置会在首次启动新版时自动迁入列表，原地址、密钥和回复方式保留。点击“使用此模型”切换，下一次请求开始使用所选服务，当前会话和历史回复保留。每个模型可单独编辑、测试和删除；新增模型不会覆盖原有配置，编辑时 Key 留空仅保留该模型自己的密钥。删除当前模型会选择列表中的其他模型，删除最后一个后需重新添加。

地址示例（仅为格式示例，需替换成实际服务器）：

| 服务 | API 根地址示例 |
| --- | --- |
| Ollama | `http://192.168.1.100:11434/v1` |
| vLLM | `http://192.168.1.100:8000/v1` |
| LM Studio | `http://192.168.1.100:1234/v1` |
| 其他兼容服务 / 反向代理 | 服务端实际提供的兼容 API 根地址 |

模型名称填写服务器实际加载或暴露的模型 ID。“保存配置”只保存当前编辑的条目；“保存并使用”同时切换到它；“保存并测试”向该模型发起一次真实请求，不切换其他模型。支持 Anthropic Messages 协议和自定义根地址。

本机已保留内网 Qwen 配置，并加入 `deepseek-v4.1-flash-1017`，兼容 API 根地址为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。凭据只保存在本机加密数据库中，未写入源码。其他电脑需在各自的模型设置中添加配置。

对于支持模式切换的自建 Qwen 服务，可选择“标准回复”关闭深度思考，或选择“深度思考”。前者通过 `chat_template_kwargs.enable_thinking=false` 请求服务器直接输出正文；“服务器默认”不发送此参数。

服务器需对客户端所在网络开放推理接口；桌面端发起 HTTP 请求，不需要在同事电脑上开放入站端口，也不需要为浏览器配置 CORS。建议通过内部网络或 HTTPS 提供推理服务。

也可用 `PBI_LLM_PROVIDER`、`PBI_LLM_MODEL`、`PBI_LLM_BASE_URL`、`PBI_LLM_API_KEY` 环境变量设置默认值；界面中保存的配置优先。`.env.example` 是变量参考，程序不自动读取 `.env` 文件。

## 使用流程

1. 在本机 Power BI Desktop 打开报表，在助手中点击“连接 Power BI”，选择对应实例。
2. 读取真实表、列、关系、度量值和 M 查询。点击右侧字段可将引用插入输入框；点击字段旁的眼睛图标可预览实际取值。聊天框按 Enter 发送，Shift+Enter 换行；中文输入法选词时按回车不会发送。
3. 在 DAX 助手中描述需求、解释或优化公式。回复流式显示，代码自动执行静态引用检查；在线模型会继续用本机引擎运行 `EVALUATE`。验证失败最多修复两轮。
4. 校准由一组筛选条件和唯一的已知正确结果组成。可添加、删除最多 10 个筛选条件，所有条件同时满足（且）；统一填写一个期望结果和一个允许的绝对误差，针对回复中的最后一个度量值执行一次校准，支持依赖前面的基础度量值。没有筛选条件时校准全模型结果。API 的 `points` 为兼容旧协议保留数组格式，但新请求最多只能包含一个校准结果。
5. 仅实跑通过的 DAX 可以审阅后写入。写入前重新读取模型、检查结构变化并重新验证；覆盖同名度量值必须显式勾选。计算表只支持新建，不覆盖已有表。写入后在 Desktop 按 Ctrl+S 保存。
6. Power Query 助手基于现有 M 查询生成清洗步骤，执行静态检查。复制到高级编辑器，在 Desktop 中应用并验证；不从外部写回或刷新 M，沿用原项目经过真实验证的限制。
7. 数据分析助手根据需求规划只读 DAX，实际查询本机模型后再形成结论。分析使用现有指标和真实取数结果，支持概览、趋势、结构贡献和多轮追问；查询及结果在回复下方留存。

无真实模型时可加载“示例模型”体验字段浏览和 AI 生成。示例模型只能静态检查。重启后，Desktop 历史会话发送新请求或重新验证代码时，会重新读取实际模型并比对快照，匹配后恢复实跑；单凭保存的快照或端口不会标记实跑通过。Desktop 离线或结构已变化时明确提示重新连接或同步，不会悄悄跳过实跑。模型在 Desktop 中修改后，请同步并开启新对话。

代码验证失败时最多自动修复两轮：第一版回复始终保留，修订内容追加在“验证修订 · 第 N 轮”下面。只把最后一版候选代码的验证结果作为当前结果，写入时仍需重新验证。若修复中断，原文和已收到的修订内容也会保存在历史中；Markdown 导出包含全部版本。仅要求评价模型时，优先给出分析与建议，修复时集中补充代码和简短说明。

历史 DAX 结果卡提供“重新实跑本组代码”，将同一回复中的基础与派生度量一起验证，不必重新请求大模型。该操作只运行临时查询，不写入 Desktop；依赖尚未写入模型且不在本组中的度量时，会显示真实的缺失引用错误。

回复按服务器返回的片段持续显示，保留已有消息、正文和代码块节点；快速片段合并到同一帧更新，不重建聊天区，也不重复播放淡入动画。阅读历史内容时不会强制滚到底部。等待过程中会显示“已连接 / 正在分析 / 正在生成”及计时；单轮生成超过 180 秒会提示超时。中断的会话会显示错误，恢复中的请求会继续查询进度。

回复使用完整 Markdown 排版：分级标题、编号列表、嵌套建议、段落、引用、表格和代码块分别显示。原始回复和导出内容保持不变，已有会话重新打开后也应用新版排版。解析器随 `frontend/vendor/` 本地提供，无需在桌面运行时联网加载。

## 字段取值预览

连接真实 Desktop 后，点击右侧字段旁的眼睛图标，查看该列的去重取值、出现行数、占总行数的比例、常见取值样例，以及总行数、不同取值数和空值统计。点击字段名称仍然向聊天框插入引用，不会打开预览。

预览默认最多返回 50 个去重值，按出现次数排序，支持搜索和清空搜索。搜索作用于模型中的实际去重取值，统计卡片和样例仍为全模型范围；没有搜索匹配不代表字段没有数据。预览不应用 Desktop 报表页面当前的筛选条件，范围为当前连接用户可读取的整个模型。空值按模型 `BLANK()` 统计，字符串列另外统计可识别的空字符串；如果源数据的空字符串已在导入时转为空值，预览无法还原其原始状态。

取值数量、字符长度或结果大小超过限制时显示“已截断”；样例和截断列表不能代表全部分类。预览只在本机读取，不调用大模型，也不会写入或刷新模型。断开 Desktop 或结构已变化时显示实际错误，不展示为无数据。

## 后台生成与页面切换

生成过程中可以切换 DAX、Power Query、数据分析助手，打开历史对话或新建会话；原任务继续在后台生成。每个页面分别保留输入草稿、Power Query 查询选择和校准条件。不同会话可以独立生成，同一会话完成当前请求后才能再次发送。

侧边栏会标记“生成中”，切换页面后顶部显示后台任务入口；生成完成会提示，未查看的结果标记“已完成”。点击对应对话或切回原助手即可继续查看进度和已经输出的文字。后台回复、代码与分析结果只更新所属会话，不会覆盖正在浏览的页面。

每次提交固定使用当时选择的模型服务、模型快照和筛选条件。之后切换模型服务只影响新请求。前端刷新或显示连接断开时，本机后端仍会继续生成，重新打开页面后可恢复查看。关闭整个桌面应用会同时停止本地后端，因此不能在退出应用后继续生成。

## 数据分析助手

先连接真实 Power BI Desktop 模型，再点击左侧“数据分析助手”。用自然语言说明指标、时间范围和分组维度，例如“按年月分析已有金额指标，说明主要变化”，或“比较不同物料组对该指标的贡献”。可以继续追问筛选范围、具体分组或比较期间；每轮重新规划并查询当前数据，不把历史数字当作本次新取数。

应用先让大模型生成查询计划，再在本机引擎实际运行查询，将结果用于生成中文分析。关键口径不明确时先追问；查询全部失败时说明原因并停止数值分析。每轮最多四条查询，每条失败可修复一次，不清空已经显示的回复。应用为结论补充本轮查询来源 `[Q1]` 等编号。

讨论分析口径时，每轮只显示一个确认问题，提供 2～4 个候选口径和“自定义口径”。候选项会展示具体含义与字段依据；可选择一项并填写补充说明，也可只填写自己的口径，然后点击“确认并继续”。例如先确认人员费用采用哪个分类字段，再按尚缺的信息确认时间范围，不把费用分类、成本中心、年份和指标放进同一句话一起追问。用户已明确的信息直接沿用，口径充分时直接查询。

未确认时不执行分析查询，也不默认勾选任何候选项。问题、候选项和确认答复随会话保存在 SQLite，导出包含完整文字；已经回复的卡片只读，旧卡片不能重复提交。仍可在聊天框直接回复。切换页面时，尚未提交的选项和补充说明保留在该页面，其他会话不受影响。

遇到“人员费用”“personnel”等业务词与分类字段的对应关系时，助手先请求检查少量相关字段，例如 `CE Category`、`Class 1/2/3`。应用生成固定的只读取值查询，返回真实匹配值、常见样例和空值统计，再由助手逐项确认采用的口径。已明确的分析需求仍可直接查询，不必逐字段扫描。

每轮最多执行 4 项字段检查、最多两轮取值与规划，单项最多保留 20 个去重值及约 6 KB 取值数据。检查记录以 `[F1]` 等编号显示在回复下方，可展开查看实际取值、检查时间和查询依据，也能重新打开字段预览。失败检查不当作空结果；没有匹配时可以更换同义词或由用户补充定义。已保存的字段检查随会话恢复、Markdown 导出和删除；普通预览不会写入会话。

每条分析下方可展开查看查询、执行状态、耗时和结果表，也可下载本次保留结果的 CSV。预览显示前 20 行；每个结果最多保留 200 行、30 列及约 24 KB 数据。超过行数或大小限制时明确显示“已截断”，下载同样只包含已保留的结果。TopN 或截断样本不能代表总体；需要总额或占比分母时，应在需求中说明或由助手另行聚合。

只接受 `EVALUATE` / 查询作用域 `DEFINE` 形式的只读 DAX，不提供写入、刷新或外部命令。单次引擎查询设置 60 秒命令超时，查询等待时发送进度心跳，整轮分析最多 10 分钟。分析查询记录独立保存在 SQLite，随会话保存、导出和删除。

## 本地存储

源码版默认存储于项目 `data/`，可用 `PBI_DATA_DIR` 指向其他目录。

- `assistant.sqlite3`：多个模型服务配置与当前选择、模型结构快照、会话、生成代码、验证结果和写入审计。
- `secret.key`：本地 API Key 的 Fernet 加密密钥。Key 不通过 API 返回，也不会写入会话。
- `assistant.log`：运行日志。
- `lib/amo/`：首次写入时从固定版本的官方 NuGet 包下载 TOM 组件；读取与 DAX 验证使用 Desktop 自带 ADOMD 组件，不需此下载。

备份时先关闭助手，再备份整个 `data/`。恢复时需同时保留数据库和 `secret.key`。数据库与密钥放在同一用户目录，加密仅避免凭据直接以明文出现在数据库中；应使用 Windows 用户权限保护该目录。`data/`、`.venv/` 和 `.env` 已加入忽略规则。

AI 生成会向所配置的模型服务器发送相关模型结构、M 查询及对话。`EVALUATE` 在本机运行，验证结果和校准误差可能在自动修复时发送给模型。数据分析模式还会发送本轮实际查询保留的结果，以及按需检查的相关字段取值、样例和空值统计，用于确认口径、解释、比较和形成结论。程序不上传 PBIX 文件；请把模型服务配置为允许处理这些数据的服务。

## 结构

```text
frontend/          JavaScript 界面、样式、SVG 图标
backend/app.py     本地 HTTP API 与同源访问检查
backend/chat.py    流式对话、验证与修复
backend/analysis.py 只读查询规划、实际取数、来源与分析
backend/powerbi.py 本机模型连接与快照
backend/settings.py 多模型服务配置、旧配置迁移与凭据加密
frontend/models.js 模型列表、添加、编辑、切换和连接测试
frontend/workspaces.js 独立页面状态、后台流与进度恢复
frontend/clarification.js 单项口径确认、候选项与补充输入
backend/clarifications.py 口径问题结构、保存和确认答复校验
frontend/fields.js 字段取值预览、搜索、空值统计与检查依据
backend/fields.py 受限的真实字段取值查询与统计
backend/database.py SQLite 存储
backend/validation.py 共享验证与组合筛选校准
backend/engine/    从原项目独立迁入的模型、DAX、M、LLM 核心
desktop.py         pywebview 桌面入口
tests/             自动测试与显式运行的真实环境检查
```

原项目只作参考，运行 V2 不依赖原目录，不启动 Streamlit。
