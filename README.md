# Power BI Assistant V2

本地桌面版 Power BI 助手，包含 DAX 助手、Power Query 助手和基于实际查询的数据分析助手。JavaScript 界面、Python 后端、SQLite 数据库；通过配置连接部署在服务器上的大模型。支持源码开发运行与 Windows CD-KEY 授权安装包。

## 授权安装包

正式安装版采用离线一机一码，支持永久授权和 7 天试用：同一机器码可由发布者用 `--type permanent` 或 `--type trial` 签发对应 CD-KEY，未指定类型时仍默认永久。试用从发码时起算 7×24 小时，重装不重置，安装、启动及使用过程中均校验。只向客户分发新版 `dist\PowerBIAssistant-Setup-2.0.2.exe`，不要分发源码、发码工具或签发私钥；旧永久密钥继续有效。签发私钥使用当前 Windows 用户的 DPAPI 加密保存在项目外；安装包只内嵌公钥。

**2.0.2 更新**：包含“同步模型后保留当前对话”修复、语义层增量更新和度量值写入时指定名称与存放表。升级前关闭助手并备份用户数据，运行新版安装包，选择原安装目录并输入本机有效的原 CD-KEY；配置、会话和业务字典保留，试用到期日不重置。具体步骤见[覆盖升级](docs/USER_GUIDE.md#从旧安装版升级到-202)。

发码、私钥备份、打包和部署方法见 [授权安装包与 CD-KEY](docs/LICENSING.md)。源码开发入口不要求授权，公开或分发源码不能依靠安装版授权阻止他人自行运行。此方案是授权控制，不是绝对防破解的加密。

## 源码启动（开发者）

Windows 10/11，Python 3.11+（已用 Python 3.12 验证）。桌面窗口使用 Edge WebView2 Runtime；本机需安装 Power BI Desktop 才能读取和验证真实模型。

```powershell
cd "E:\AI_Project\Power BI Assistant V2"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\.venv\Scripts\python.exe desktop.py
```

依赖安装后也可双击 `start.bat`。前端采用原生 JavaScript ES Modules；运行桌面版无需 Node.js、npm 或前端构建。`package.json` 中的依赖仅用于前端开发测试。

开发预览：

```powershell
.\.venv\Scripts\python.exe desktop.py --browser --port 8765
```

默认使用自动分配的本地端口，只监听 `127.0.0.1`。关闭桌面窗口会退出对应本地服务。

## 连接服务器大模型

点击左下角“模型服务设置”，或输入框下方的模型名称，打开已保存的模型列表。点击“添加模型”，填写显示名称、API 协议、服务器 API 根地址、模型名称 / ID 和 API Key。无鉴权的内部服务可将 Key 填为 `local`。

支持保存多个模型。旧版的单模型配置会在首次启动新版时自动迁入列表，原地址和密钥保留；尚无强度设置的配置统一采用低强度。点击“使用此模型”切换，下一次请求开始使用所选服务，当前会话和历史回复保留。每个模型可单独编辑、测试和删除；新增模型不会覆盖原有配置，编辑时 Key 留空仅保留该模型自己的密钥。删除当前模型会选择列表中的其他模型，删除最后一个后需重新添加。

地址示例（仅为格式示例，需替换成实际服务器）：

| 服务 | API 根地址示例 |
| --- | --- |
| Ollama | `http://192.168.1.100:11434/v1` |
| vLLM | `http://192.168.1.100:8000/v1` |
| LM Studio | `http://192.168.1.100:1234/v1` |
| 其他兼容服务 / 反向代理 | 服务端实际提供的兼容 API 根地址 |

模型名称填写服务器实际加载或暴露的模型 ID。“保存配置”只保存当前编辑的条目；“保存并使用”同时切换到它；“保存并测试”向该模型发起一次真实请求，不切换其他模型。支持 Anthropic Messages 协议和自定义根地址。

本机已保留内网 Qwen 配置，并加入 `deepseek-v4.1-flash-1017`，兼容 API 根地址为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。凭据只保存在本机加密数据库中，未写入源码。其他电脑需在各自的模型设置中添加配置。

思考强度直接显示在每张模型卡片上，不再放在“编辑”中。默认“低强度 · 快速”，可按需一键切换“高强度 · 深入”，每个模型独立保存，重启不会重置已选强度。支持原生强度的 DeepSeek、GLM、Kimi、MiniMax、豆包版本发送 `reasoning_effort=low/high`；仅支持开关的千问、混元及部分旧版本以“低强度=标准回复、高强度=开启思考”兼容，并明确显示实际模式。参数按模型版本与接口匹配，固定思考、文心／千帆等尚未确认的接口、未知代理或 Anthropic Messages 协议显示限制并禁用强度切换，不假装已经降低强度。具体范围和参数依据见[使用说明](docs/USER_GUIDE.md#思考强度与等待时间)。

每个模型独立设置“单次输出额度”（`max_tokens`），默认 16000，可填 256～131072，须符合服务器和模型支持的范围。DAX、Power Query、分析规划/修复/总结及语义梳理都使用此设置，不再为分析结论固定设置 8000。推理模型的思考可能消耗输出额度；输出额度、输入上下文长度和等待时限是不同参数。旧配置自动采用新默认值，旧客户端编辑配置时不会清除已保存的额度。

分析已取得数据但结论正文为空时，最多复用本轮查询结果与图片重试一次；已适配接口在重试时临时降低到低强度（开关型接口为标准回复），不修改已保存配置，也不重查 Desktop。GLM-5.3 等固定思考但可调强度的模型不会收到无效的关闭指令。已有部分正文时不会自动重写；长度限制、过滤、上游中断及超时分别提示，文字与查询结果保留。重试仍受同一轮总时限约束。每次流式请求的阶段、结束原因、请求 ID、服务器提供的 token 用量和是否收到思考数据保存在本机 SQLite `llm_generations` 与日志中；不会记录思考正文。历史消息接口的 `generations` 字段可用于排查，旧请求无法补回当时未记录的用量。

每个模型可分别设置“无新数据等待时间”（默认 90 秒，范围 30～600 秒）与“单次生成总时限”（默认 900 秒，即 15 分钟，范围 180～7200 秒）。正文及思考数据持续返回时会重置等待计时；默认连续 30 秒无新数据先提示继续等待，恢复后继续追加原回复。等待时间设得较短时，提示相应提前。只有连续无新数据达到等待时限，或达到总时限才中断。客户端心跳不计为模型活动。数据分析整轮（规划、查值、查询及总结）共用设置的总时限；语义梳理按批次使用此时限。旧配置缺少等待字段时使用默认值；修改从下一次请求生效。

服务器需对客户端所在网络开放推理接口；桌面端发起 HTTP 请求，不需要在同事电脑上开放入站端口，也不需要为浏览器配置 CORS。建议通过内部网络或 HTTPS 提供推理服务。

也可用 `PBI_LLM_PROVIDER`、`PBI_LLM_MODEL`、`PBI_LLM_BASE_URL`、`PBI_LLM_API_KEY` 环境变量设置默认值；界面中保存的配置优先。`.env.example` 是变量参考，程序不自动读取 `.env` 文件。

## 图片与截图

DAX、Power Query 和数据分析助手都支持附图。点击输入框上方“＋ 图片”选择文件，或将图片拖入输入框；也可在截图后直接按 Ctrl+V 粘贴。点击“截图”会打开 Windows 截图工具，框选完成后回到输入框按 Ctrl+V 添加。添加后显示缩略图，可点击查看、移除，输入需求后按 Enter 发送；只有图片时也可发送。

每条消息最多 4 张，支持 PNG、JPEG、WebP，原文件每张不超过 8 MB。后端验证真实图片并去除附加元数据，长边缩至最多 2048 像素，保存为最多 2 MB 的 PNG/JPEG。添加图片只上传到本机；发送消息时，相关图片的真实内容才随对话提供给所选多模态模型。OpenAI 兼容和 Anthropic Messages 两类服务均支持图片请求；服务或模型不接受图片时明确显示错误，不悄悄忽略附件。

图片草稿按页面/会话独立保留，切换助手不会把正在上传的图片加到别的页面。发送后在用户消息中显示图片，后台生成、切换页面及重启助手后可在历史查看。后续追问会携带近期附图，每次模型请求最多 8 张历史/本轮图片，超出的较早图片明确注明未重发，需要时重新附图。未发送的草稿只在当前应用运行期间保留；移除时删除本机暂存，超过两天的未发送暂存图在启动时清理。

图片随消息保存在 SQLite，删除会话时一起删除。Markdown 导出内嵌图片数据，离线仍可查看。截图用来理解界面、错误提示或业务需求，图上的数值不会冒充本轮实际查询结果；数据分析仍使用真实 Desktop 查询结果形成结论。

已使用当前保存的 `deepseek-v4.1-flash-1017` 进行真实识图测试，准确识别程序生成图片的左红右蓝；没有发送业务数据或用户截图。复测命令：`.venv\Scripts\python.exe -m scripts.verify_vision`。图片验证依赖 Pillow，已加入 `requirements.txt`，首次更新需安装依赖后重启。

## 使用流程

1. 在本机 Power BI Desktop 打开报表，在助手中点击“连接 Power BI”，选择对应实例。
2. 读取真实表、列、关系、度量值和 M 查询。点击右侧字段可将引用插入输入框；点击字段旁的眼睛图标可预览实际取值。聊天框按 Enter 发送，Shift+Enter 换行；中文输入法选词时按回车不会发送。
3. 先打开右侧“模型语义层”，完成模型词典梳理并审阅关键业务定义，再在 DAX 助手中描述需求、解释或优化公式。回复流式显示，代码自动执行静态引用检查；在线模型会继续用本机引擎运行 `EVALUATE`。验证失败最多修复两轮。
4. 校准由一组筛选条件和唯一的已知正确结果组成。可添加、删除最多 10 个筛选条件，所有条件同时满足（且）；统一填写一个期望结果和一个允许的绝对误差，针对回复中的最后一个度量值执行一次校准，支持依赖前面的基础度量值。没有筛选条件时校准全模型结果。API 的 `points` 为兼容旧协议保留数组格式，但新请求最多只能包含一个校准结果。
5. 仅实跑通过的 DAX 可以审阅后写入。在确认窗口中可修改“度量值名称”，并从“存放表”选择模型中的已有表；默认为生成时的名称和表。写入前按最终名称与存放表重新读取模型、检查结构变化、实跑验证及原有校准。所选表中存在同名度量时必须显式勾选覆盖；其他表中的同名度量或所选表中的同名字段会提示冲突。成功后聊天结果卡、本地记录和审计保存实际名称与存放表。计算表只支持新建，不覆盖已有表。写入后在 Desktop 按 Ctrl+S 保存。
6. Power Query 助手基于现有 M 查询生成清洗步骤，执行静态检查。复制到高级编辑器，在 Desktop 中应用并验证；不从外部写回或刷新 M，沿用原项目经过真实验证的限制。
7. 数据分析助手根据需求规划只读 DAX，实际查询本机模型后再形成结论。分析使用现有指标和真实取数结果，支持概览、趋势、结构贡献和多轮追问；查询及结果在回复下方留存。

无真实模型时可加载“示例模型”体验字段浏览和 AI 生成。示例模型只能静态检查。Desktop 连接支持自动恢复：界面每 3 秒更新当前和生成中会话的连接状态，后端正常时约每 20 秒核对一次真实结构；临时失败先短暂重试三次，仍未恢复时按 2、5、10、20、30 秒退避继续检查。检查不会排队阻塞已有 Desktop 查询。

助手重启或报表重开后，按保存的引擎身份、报表名称和可取得的文件路径重新定位，并核对表、字段类型、关系、公式与 M 查询。只有身份匹配唯一且结构一致才自动恢复原模型记录和会话；语义词典、截图、历史回复和草稿保留，更换引擎时清除旧取值缓存。结构有变化显示“结构待同步”，多个可能报表显示“请选择报表”，报表未打开时显示“等待 Desktop”。没有报表身份的旧快照不会仅凭相似结构跳到其他端口。模型在 Desktop 中修改后，点击右侧“同步模型”，**同步后继续当前对话**。

同步会读取新快照，并将当前对话切换到该快照，保留原对话 ID、聊天记录、图片、草稿和历史查询结果；已保存的语义定义按增量复用。同步前的助手回复标记为“同步前回复”，后续分析按当前模型重新查询，历史结果继续保留供核对。原有代码重新实跑和写入也使用该对话的最新模型。当前对话正在生成时，先完成或中止后再同步；其他对话可继续后台生成。同步请求期间切换页面不会丢失草稿，也不会把同步结果应用到另一页面。

每次生成、查询、实跑或写入前仍会核对实际模型，绿色状态不能替代该检查。数据分析的只读查询若发生可识别的连接断开，会重新核对连接并重试一次；语法错误、普通查询超时、模型写入和已结束的聊天请求不会被自动重放。状态刷新只更新连接信息，不重画聊天区或字段树。真实只读重连复测：`.venv\Scripts\python.exe -m scripts.verify_reconnect`。

代码验证失败时最多自动修复两轮：第一版回复始终保留，修订内容追加在“验证修订 · 第 N 轮”下面。只把最后一版候选代码的验证结果作为当前结果，写入时仍需重新验证。若修复中断，原文和已收到的修订内容也会保存在历史中；Markdown 导出包含全部版本。仅要求评价模型时，优先给出分析与建议，修复时集中补充代码和简短说明。

历史 DAX 结果卡提供“重新实跑本组代码”，将同一回复中的基础与派生度量一起验证，不必重新请求大模型。该操作只运行临时查询，不写入 Desktop；依赖尚未写入模型且不在本组中的度量时，会显示真实的缺失引用错误。

回复按服务器返回的片段持续显示，保留已有消息、正文和代码块节点；快速片段合并到同一帧更新，不重建聊天区，也不重复播放淡入动画。阅读历史内容时不会强制滚到底部。等待过程中会显示“已连接 / 正在分析 / 正在生成”及计时，不再在固定 180 秒时中断正常输出。超时或中断后，已收到的文字、修订内容和已执行的分析查询结果保存在会话中，可继续查看和导出；恢复中的请求会继续查询进度。

回复使用完整 Markdown 排版：分级标题、编号列表、嵌套建议、段落、引用、表格和代码块分别显示。原始回复和导出内容保持不变，已有会话重新打开后也应用新版排版。解析器随 `frontend/vendor/` 本地提供，无需在桌面运行时联网加载。

## 模型语义层

连接真实模型后先在本机整理全部表、字段和度量值，读取已有描述、实际数据类型、显示格式、源字段、公式和关系。打开右侧“模型语义层”，可查看事实依据，搜索业务名称和字段，编辑业务含义、角色、单位和别名，并逐条确认。没有描述或业务依据的条目明确标记未知，模型中的取值存在不等于用户要按该字段筛选。

词典区分“业务含义未知”“候选含义 · 待确认”“用户已确认”。点击“开始梳理模型语义”会将界面注明的模型结构、公式和描述发送到所显示的模型服务，分批解释待梳理对象；连接本身不自动调用外部模型。候选建议不会自动确认，单位和币种没有依据时保持未知。也可手动填写并确认全部定义，完成本地词典。首次连接没有已有解释时需先建立初始词典；后续更新可以沿用历史语义继续进行 DAX 生成和数据分析。“完成梳理”表示词典覆盖完成，不代表全部业务定义已获确认。

每批返回内容都校验对象 ID、字段格式和完整性。格式不合规时只修复当前批次；若梳理中断，已完成的批次保留，点击“继续梳理”从未完成处继续。模型结构改变时重新检查覆盖范围，不把旧结构的进度当作新结构已经完成。

DAX 助手和数据分析助手共享词典及字段取值证据。遇到 `0257` 等带前导零的编号时，先用本机只读查询精确检查真实取值，不再按字段名猜测或推荐无关的日历字段。只问“0257 是什么意思 / 属于哪个字段”时，直接解释实际匹配及来源，不弹出筛选确认卡；字段名称、候选业务定义和用户已确认的含义仍分开标明，具体公司或对象名称没有依据时不编造。

需要生成 DAX 或分析时，查值范围完整且只有一个匹配字段，可以作为本轮建议口径，并将实际证据提供给模型；这不会自动变成用户确认或全局业务定义。出现重号、检查不完整或与用户指定的业务含义冲突时，再逐项确认，选项优先列出已验证包含该编号的字段。编号按文本保留前导零，不把 `0257` 当作数值 `257`。旧助手回复中的自加口径不会视作用户确认；用户明确指定的完整字段引用或已确认别名仍优先。

编号检查只返回各字段是否有精确匹配，不读取金额度量。最多检查 96 个文本或未知类型字段，分批执行，单条命令最多 5 秒、单个编号最多约 15 秒；达到数量、时间上限或发生错误时标明检查未完成。检查时立即显示进度并保持连接，结果含时间与范围；有限范围的匹配不代表已确定全部业务含义。

语义词典、报表身份与编号确认记录保存在 SQLite。重新打开 Desktop 后，点击连接即可按报表名称自动匹配已有词典；能识别文件路径时同时核对路径，不再依赖每次变化的 PID 和端口。连接列表和词典中显示报表名称。字段、关系、公式与描述未变化时直接复用，候选解释、用户确认状态与业务别名保留；字段顺序或取值数量变化不会要求重建。同一模型快照写入后的同步也会保留未变化条目。

Desktop 有更新时点击右侧同步模型，再打开“模型语义层”：面板显示保留、新增、修改或受影响、删除的数量及变更原因，可以只看本次变更，点击“仅梳理待更新 N 项”。字段类型、说明、公式、格式、来源或关系变化只更新对应条目及可识别的依赖项；共享 M 查询或参数变化只影响引用它们的查询及下游对象。删除的对象退出当前词典，变更前定义保留供核对，失效的确认不会继续当作当前业务口径。没有待更新项时不会再次发起整份梳理，中断后仅继续剩余条目。

**已有历史语义层时，增量更新待处理、正在梳理或梳理失败都可以继续提问，不会因词典未更新完而禁止发送。** DAX 和分析使用当前结构及未变化的定义；涉及未知或已变化的业务含义时按需查值、说明不确定性或逐项确认。只有首次连接、完全没有已有解释时，才需要先建立初始词典。结构同步仍会核对真实 Desktop；断线或模型尚未同步不会跳过连接验证。

旧版词典未记录报表名时，结构一致且只有一个可确定的历史来源会自动关联并记住报表名。存在多个可能来源、同名不同路径、或报表重命名/另存为时，可在“模型语义层 → 关联已有词典”选择结构一致的历史词典，点击“关联并复用”，不需要调用大模型从头生成。无法自动取得名称时，连接窗口可以手动填写报表名，之后使用相同名称匹配。未保存的无标题报表不自动按通用标题匹配。

词典复用不会复用旧引擎的字段取值或查询结果；实际值仍按需重新读取。编号筛选的用户确认仍只属于原会话。建立或匹配词典不会自动扫描整表业务数据，也不会写入或刷新 Desktop 模型。

## 字段取值预览

连接真实 Desktop 后，点击右侧字段旁的眼睛图标，查看该列的去重取值、出现行数、占总行数的比例、常见取值样例，以及总行数、不同取值数和空值统计。点击字段名称仍然向聊天框插入引用，不会打开预览。

从业务字典点击“查看实际取值”后，可用“返回业务字典”、右上角关闭按钮或 Esc 返回原字典，保留搜索内容、只看待确认项的选择和滚动位置。正在读取或读取失败时也可以返回；直接从模型字段或聊天依据打开的预览，关闭后回到工作区。

预览默认最多返回 50 个去重值，按出现次数排序，支持搜索和清空搜索。搜索作用于模型中的实际去重取值，统计卡片和样例仍为全模型范围；没有搜索匹配不代表字段没有数据。预览不应用 Desktop 报表页面当前的筛选条件，范围为当前连接用户可读取的整个模型。空值按模型 `BLANK()` 统计，字符串列另外统计可识别的空字符串；如果源数据的空字符串已在导入时转为空值，预览无法还原其原始状态。

取值数量、字符长度或结果大小超过限制时显示“已截断”；样例和截断列表不能代表全部分类。预览只在本机读取，不调用大模型，也不会写入或刷新模型。有限的取值、统计及时间保存到本机 SQLite，供后续编号定位优先检查相关字段；再次解释或生成时仍重新查值，不把旧预览当作当前事实。断开 Desktop 或结构已变化时显示实际错误，不展示为无数据。

## 后台生成与页面切换

生成过程中可以切换 DAX、Power Query、数据分析助手，打开历史对话或新建会话；原任务继续在后台生成。每个页面分别保留输入草稿、Power Query 查询选择和校准条件。不同会话可以独立生成，同一会话完成当前请求后才能再次发送。

输入框右下角保留发送按钮，旁边有独立的“中止”按钮，仅在当前会话生成时启用。点击后停止本轮后续生成、查询、验证修复和总结，关闭当前模型响应流，并向正在执行的 Desktop 只读查询发送取消请求；已输出文字、已完成查询结果和已发送截图保留，状态标记为“已中止”，随后可继续发送新消息。中止只影响所选会话，切换页面本身仍不会中止。尚未提交的请求会恢复为草稿；迟到的旧中止请求不能停止新一轮生成。查询的实际取消完成时间取决于引擎，服务端算力回收取决于模型服务对连接关闭的处理。

侧边栏会标记“生成中”，切换页面后顶部显示后台任务入口；生成完成会提示，未查看的结果标记“已完成”。点击对应对话或切回原助手即可继续查看进度和已经输出的文字。后台回复、代码与分析结果只更新所属会话，不会覆盖正在浏览的页面。

每次提交固定使用当时选择的模型服务、模型快照和筛选条件。之后切换模型服务只影响新请求。前端刷新或显示连接断开时，本机后端仍会继续生成，重新打开页面后可恢复查看。关闭整个桌面应用会同时停止本地后端，因此不能在退出应用后继续生成。

## 数据分析助手

先连接真实 Power BI Desktop 模型，再点击左侧“数据分析助手”。用自然语言说明指标、时间范围和分组维度，例如“按年月分析已有金额指标，说明主要变化”，或“比较不同物料组对该指标的贡献”。可以继续追问筛选范围、具体分组或比较期间；每轮重新规划并查询当前数据，不把历史数字当作本次新取数。

应用先让大模型生成查询计划，再在本机引擎实际运行查询，将结果用于生成中文分析。关键口径不明确时先追问；查询全部失败时说明原因并停止数值分析。每轮最多四条查询，每条失败可修复一次，不清空已经显示的回复。应用为结论补充本轮查询来源 `[Q1]` 等编号。

讨论分析口径时，每轮只显示一个确认问题，提供 2～4 个候选口径和“自定义口径”。候选项会展示具体含义与字段依据；可选择一项并填写补充说明，也可只填写自己的口径，然后点击“确认并继续”。例如先确认人员费用采用哪个分类字段，再按尚缺的信息确认时间范围，不把费用分类、成本中心、年份和指标放进同一句话一起追问。用户已明确的信息直接沿用，口径充分时直接查询。

未确认时不执行分析查询，也不默认勾选任何候选项。问题、候选项和确认答复随会话保存在 SQLite，导出包含完整文字；已经回复的卡片只读，旧卡片不能重复提交。仍可在聊天框直接回复。切换页面时，尚未提交的选项和补充说明保留在该页面，其他会话不受影响。

遇到“人员费用”“personnel”等业务词与分类字段的对应关系时，助手先请求检查少量相关字段，例如 `CE Category`、`Class 1/2/3`。应用生成固定的只读取值查询，返回真实匹配值、常见样例和空值统计，再由助手逐项确认采用的口径。已明确的分析需求仍可直接查询，不必逐字段扫描。

自动字段检查不设固定项数上限，可根据需求检查超过 4 项的相关字段；仍最多执行两轮取值与规划，重复检查会去重，整轮分析遵循所选模型设置的总时限（默认 15 分钟）。单项最多保留 20 个去重值及约 6 KB 取值数据。检查记录以 `[F1]` 等编号显示在回复下方，可展开查看实际取值、检查时间和查询依据，也能重新打开字段预览。失败检查不当作空结果；没有匹配时可以更换同义词或由用户补充定义。已保存的字段检查随会话恢复、Markdown 导出和删除；普通预览不会写入会话。

每条分析下方可展开查看查询、执行状态、耗时和结果表，也可下载本次保留结果的 CSV。预览显示前 20 行；每个结果最多保留 200 行、30 列及约 24 KB 数据。超过行数或大小限制时明确显示“已截断”，下载同样只包含已保留的结果。TopN 或截断样本不能代表总体；需要总额或占比分母时，应在需求中说明或由助手另行聚合。

只接受 `EVALUATE` / 查询作用域 `DEFINE` 形式的只读 DAX，不提供写入、刷新或外部命令。单次引擎查询设置 60 秒命令超时，查询等待时发送进度心跳，整轮分析总时限可在所选模型的设置中调整。分析查询记录独立保存在 SQLite，随会话保存、导出和删除。

## 本地存储

源码版默认存储于项目 `data/`，可用 `PBI_DATA_DIR` 指向其他目录。

- `assistant.sqlite3`：多个模型服务配置与当前选择、模型结构快照、会话与图片附件、生成代码、验证结果和写入审计。
- `secret.key`：本地 API Key 的 Fernet 加密密钥。Key 不通过 API 返回，也不会写入会话。
- `assistant.log`：运行日志。
- `lib/amo/`：首次写入时从固定版本的官方 NuGet 包下载 TOM 组件；读取与 DAX 验证使用 Desktop 自带 ADOMD 组件，不需此下载。

备份时先关闭助手，再备份整个 `data/`。恢复时需同时保留数据库和 `secret.key`。数据库与密钥放在同一用户目录，加密仅避免凭据直接以明文出现在数据库中；应使用 Windows 用户权限保护该目录。`data/`、`.venv/` 和 `.env` 已加入忽略规则。

AI 生成会向所配置的模型服务器发送相关模型结构、M 查询及对话。`EVALUATE` 在本机运行，验证结果和校准误差可能在自动修复时发送给模型。DAX 和数据分析会发送相关编号的实际字段匹配证据；编号归属能在本地解释时不调用模型。数据分析模式还会发送本轮实际查询保留的结果，以及按需检查的相关字段取值、样例和空值统计，用于确认口径、解释、比较和形成结论。程序不上传 PBIX 文件；请把模型服务配置为允许处理这些数据的服务。

backend/clarifications.py 口径问题结构、保存和确认答复校验

backend/reports.py 报表名称与路径识别、跨运行实例的模型结构匹配
frontend/semantics.js 语义词典查看、编辑和分批梳理进度
backend/database.py SQLite 存储
backend/validation.py 共享验证与组合筛选校准
backend/engine/    从原项目独立迁入的模型、DAX、M、LLM 核心
desktop.py         pywebview 桌面入口
tests/             自动测试与显式运行的真实环境检查
