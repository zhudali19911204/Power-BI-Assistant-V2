# Power BI Assistant V2 详细使用说明

本文面向实际使用软件的报表开发者和业务分析人员，按“安装 → 配置 → 连接 → 使用 → 保存”的顺序介绍操作。

适用范围：当前仓库的 Windows 桌面版与源码运行版。文档更新日期：2026-11-09。安装包版本号可能随发布变化，以下以 `2.0.0` 为例。

> **使用前请牢记：**助手读取的是本机 Power BI Desktop 中已打开的模型；AI 推理由你配置的模型服务完成。“检查通过”不一定代表业务口径正确，写入或应用脚本前应审阅并备份报表。

## 软件能力与边界

### 三种工作空间

| 工作空间 | 适合做什么 | 结果如何使用 |
| --- | --- | --- |
| DAX 助手 | 根据业务需求生成度量值或计算表，解释公式，检查和优化 DAX | 查看自动验证结果；符合写入条件后，由你审阅并确认写入 |
| Power Query | 基于模型中已有的 M 查询生成清洗、转换与优化脚本 | 复制到 Desktop 的 Power Query 高级编辑器，再应用和验证 |
| 数据分析助手 | 使用已有指标分析概览、趋势、分组差异和贡献 | 查看中文分析、实际 DAX 查询与结果表，按需下载 CSV |

共同支持：模型结构浏览、历史对话、图片输入、多个模型服务配置和 Markdown 对话导出。真实模型下的 DAX 与数据分析还共享模型语义词典和字段取值证据。

### 两种“模型”不要混淆

- **Power BI 模型**：报表中的表、字段、关系、度量值和查询，是业务数据来源。入口是右上角“连接 Power BI”。
- **大模型服务**：用于理解需求、生成代码和分析文字的 AI 服务。入口是左下角“模型服务设置”。

连接 Power BI 不等于已经配置 AI；AI 测试成功也不等于已经连接到报表。

### 当前不提供的能力

- 不直接上传、解析 PBIX 文件来替代 Desktop 实时连接，也不是 Power BI Service 云端报表连接器。
- 不自动继承 Desktop 报表页面上的切片器、视觉对象筛选或当前选中项。需要的筛选范围应在需求或校准条件中明确说明。
- 不从外部写回、应用或刷新 Power Query M 脚本。
- 数据分析只读，不写入或刷新模型；下载的结果也不是全模型原始数据导出。
- 没有经过实跑的代码不能使用受控写入功能；计算表不支持覆盖已有同名表。
- 关闭整个助手后，本地服务会退出，未完成任务不会继续在云端后台替你运行。

## 安装与启动

### 环境准备

| 条件 | 说明 |
| --- | --- |
| Windows 10/11 | 当前桌面应用及 Desktop 引擎连接面向 Windows |
| Edge WebView2 Runtime | 用于显示桌面窗口；窗口无法启动时先检查此运行时 |
| Power BI Desktop | 读取、查询、校准和写入真实模型时必需；报表须在本机打开 |
| 可访问的模型服务 | 准备 API 协议、根地址、模型 ID、API Key；图片功能还要求模型支持视觉输入 |
| 网络条件 | 能访问所选模型服务；首次 DAX 写入还可能需要下载官方 TOM 组件 |

正式安装版不要求用户安装 Python、Node.js 或 npm。源码运行版需要 Python 3.11+，项目已用 Python 3.12 验证；正常运行桌面界面不需要前端构建。

### 方式一：使用正式授权安装包

1. 从可信发布者取得 `PowerBIAssistant-Setup-2.0.0.exe`。
2. 运行安装包，在“软件授权”页复制本机机器码，交给软件发布者。
3. 将发布者返回的完整 CD-KEY 粘贴到输入框，再继续安装。
4. 完成后，从安装生成的应用入口启动 Power BI Assistant。
5. 首次使用时自行添加大模型服务配置，并连接本机报表。安装包不携带其他用户的 API Key 或历史会话。

机器码以 `PBI2M-` 开头，CD-KEY 以 `PBI2K-` 开头；二者不同，不能相互代替。授权为离线一机一码、永久有效，安装后每次启动自动校验，无需反复输入。

默认按当前 Windows 用户安装到 `%LOCALAPPDATA%\Programs\PowerBIAssistant`，不要求管理员权限。重装助手通常不改变机器码；更换电脑或重装 Windows 后，应重新取得该机器对应的授权。不要删除或替换程序旁的 `license.key`。

当前发行程序未使用商业代码签名证书签名，Windows 可能提示未知发布者。应先向发布者核实文件来源，不建议关闭系统防护来绕过提示。

管理员发码、静默部署和发布包构建请参阅 [授权安装包与 CD-KEY](LICENSING.md)。

### 方式二：从源码启动

在 PowerShell 中进入项目目录，执行以下命令。第一行路径请替换为实际解压或克隆位置。

```powershell
cd "E:\AI_Project\Power BI Assistant V2"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\.venv\Scripts\python.exe desktop.py
```

完成依赖安装后，也可以双击项目根目录的 `start.bat`。此脚本不会代替你创建虚拟环境或安装依赖。源码开发入口不要求安装版 CD-KEY。

供开发排查使用的浏览器预览：

```powershell
.\.venv\Scripts\python.exe desktop.py --browser --port 8765
```

浏览器访问 `http://127.0.0.1:8765`。默认桌面模式使用自动分配的端口，只监听本机 `127.0.0.1`，不是对外共享的 Web 服务。浏览器预览由当前终端运行服务，结束调试时在该终端按 Ctrl+C；仅关闭浏览器标签页不等于停止服务。

## 第一次使用：从启动到第一条回复

建议首次使用选择一个已备份的报表，先完成只读流程，不立即写入模型。

1. **打开报表。**在 Power BI Desktop 中打开目标文件，等待模型加载完成。
2. **启动助手。**确认主界面正常显示。
3. **配置 AI。**点击“模型服务设置”→“添加模型”，填写服务信息；先“保存并测试”，成功后“保存并使用”。
4. **连接报表。**点击右上角“连接 Power BI”，按报表名称和路径选择正确实例。
5. **检查连接。**右侧应显示表、字段和度量值数量，连接状态显示“Desktop 已连接”。
6. **完成语义梳理。**首次连接可能自动打开“模型语义层”。确认显示的模型服务与发送范围后，点击“开始梳理模型语义”；完成后审阅关键业务字段、单位和指标定义。
7. **提出一个明确问题。**例如在 DAX 助手中输入“请解释 `[总销售额]` 的计算逻辑及筛选上下文，不需要改写公式”。请将示例名称替换为你的实际指标，也可以点击右侧度量值插入引用。
8. **核对结果。**查看回复依据；如果回复包含 DAX，区分静态检查与实跑结果。需要修改报表时，再按本文的校准和写入步骤操作。

**没有报表，只想体验界面：**点击“连接 Power BI”→“体验示例模型”，再配置模型服务。示例可用于字段浏览、DAX 生成和示例 M 查询体验，但没有可执行的真实数据引擎，不能做真实分析、校准、实跑或写入。AI 生成仍需要模型服务。

## 配置大模型服务

### 添加并测试

1. 点击“模型服务设置”或输入框下方的模型名称。
2. 点击“添加模型”。
3. 按下表填写参数。
4. 点击“保存并测试”，检查提示是否成功。
5. 点击“保存并使用”，或返回列表点击“使用此模型”，确认该条目标为“当前使用”。

| 字段 | 填写方法 |
| --- | --- |
| 显示名称 | 自己容易识别的名称，例如“内网 Qwen”“业务分析模型” |
| API 协议 | 选择“OpenAI 兼容”或“Anthropic Messages”，必须与服务端接口一致 |
| 服务器 API 地址 | 填服务商的 API 根地址，不是聊天网页地址；Anthropic 官方服务可留空 |
| 模型名称 / ID | 服务端实际暴露的 ID，不要仅填写自定义显示名称 |
| API Key | 使用该服务的有效密钥；无鉴权的内部兼容服务可填 `local` |
| 回复方式 | 支持阿里云百炼、DeepSeek 官方接口和自建 Qwen 的思考开关；其他服务或 Anthropic Messages 协议选择“服务器默认” |
| 单次输出额度 | 默认 16000 token，允许 256～131072，须符合所选模型的范围；思考可能占用输出额度 |
| 无新数据等待时间 | 默认 90 秒，允许 30～600 秒 |
| 单次生成总时限 | 默认 900 秒，即 15 分钟，允许 180～7200 秒；不能小于无新数据等待时间 |

兼容接口地址格式示例，均须替换为实际服务器：

| 服务 | 根地址示例 |
| --- | --- |
| Ollama | `http://192.168.1.100:11434/v1` |
| vLLM | `http://192.168.1.100:8000/v1` |
| LM Studio | `http://192.168.1.100:1234/v1` |
| 其他云端兼容接口 | `https://your-provider.example/v1`，以服务商文档为准 |

不要自行把根地址改成 `/chat/completions` 等单个操作地址。局域网服务需确认推理接口已开放给本机所在网络；建议使用可信内网或 HTTPS。

### 理解三个保存按钮

| 按钮 | 效果 |
| --- | --- |
| 保存配置 | 保存当前条目，不主动切换到另一个模型 |
| 保存并使用 | 保存并将该条目设为当前使用 |
| 保存并测试 | 保存并向该模型发送一次真实测试请求，不切换其他当前模型 |

列表中的“测试连接”同样会发起真实请求，可能产生服务商调用费用。普通文本测试成功不代表模型支持图片，图片能力需使用支持视觉输入的模型另行确认。

### 编辑、切换和删除

- 可保存多个服务；新增条目不会覆盖原有配置。
- 编辑已有条目时，API Key 留空表示保留**该条目自己的密钥**；需要清除时勾选“清除此模型已保存的 Key”。
- 点击“使用此模型”后，下一次请求使用新服务，已有会话和历史内容保留。
- 已提交的生成任务固定使用提交时的模型配置；中途切换服务不会更换该任务的模型。
- 删除当前条目会选择列表中的其他模型；删除最后一个后，需重新添加才能继续调用 AI。
- API Key 加密保存在本机，不在界面回显。更换服务后，同一会话中的相关历史内容可能会发送到新服务，切换前应确认数据权限。

### 回复方式与等待时间

“标准回复 · 关闭深度思考”和“深度思考”会按 OpenAI 兼容服务器地址选择对应参数：阿里云百炼使用顶层 `enable_thinking`，DeepSeek 官方接口使用 `thinking.type`，自建 Qwen 使用 `chat_template_kwargs.enable_thinking`。其他服务或 Anthropic Messages 协议应选“服务器默认”。模型思考数据会计入活动检测，但不作为正文显示或保存。

“单次输出额度”用于 DAX、Power Query、分析规划/修复/总结和语义梳理的每次生成请求。它不是输入上下文容量，也不是等待时间。默认 16000 token；推理模型的思考可能占用这个额度。出现“模型因长度限制停止”时，按模型实际支持的范围适当提高额度或缩小任务，不能仅延长等待时间。各模型单独保存，旧配置自动使用默认值。

持续收到正文或思考数据时，无新数据计时会重置。默认连续 30 秒没有新数据先提示继续等待，恢复输出后继续追加原回复；等待设置较短时提示会提前。达到无新数据等待上限或生成总时限才会中断，界面心跳不算模型输出。

数据分析的规划、查值、查询和总结共用整轮总时限；语义梳理按批次使用此时限。设置修改从下一次请求生效；单次 Desktop 查询另有自己的超时限制。

开发者也可以设置 `PBI_LLM_PROVIDER`、`PBI_LLM_MODEL`、`PBI_LLM_BASE_URL`、`PBI_LLM_API_KEY` 环境变量作为默认配置，界面保存的配置优先。项目中的 `.env.example` 只是参考，程序**不会自动读取 `.env` 文件**。

## 连接与同步 Power BI 模型

### 连接正确的报表

1. 在本机 Desktop 中打开报表并保持运行。
2. 在助手中点击“连接 Power BI”。
3. 按报表名称、文件路径选择实例；同时打开多个文件时，不要只按端口猜测。
4. 如果列表为空，等待 Desktop 完成加载后点击“重新扫描”。
5. 若无法识别报表名，连接窗口会提供名称输入框；填写以后也会使用的固定名称，便于匹配语义词典。
6. 连接后检查右侧模型名和字段是否确实属于目标报表。

连接会读取表、列、关系、度量值及可用 M 查询，不自动调用外部模型解释语义，也不修改报表。选择一个模型会进入使用该模型的新对话，不会把原会话改绑到另一个报表。

### 连接状态与自动恢复

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| Desktop 已连接 / 本机实时连接 | 上次检查已读取真实引擎并核对结构 | 任务执行前仍会重新核对连接 |
| 正在检测连接 / 自动重连中 | 正在恢复原报表连接 | 保持 Desktop 打开，等待自动恢复 |
| 等待 Desktop | 原报表暂不可用，仍会继续尝试 | 打开对应报表；必要时手动重新扫描 |
| 结构待同步 | 真实表、字段、关系或公式与快照不同 | 同步模型并开启新对话 |
| 请选择报表 | 存在多个可能匹配的实例 | 手动选择实际报表，助手不会随机切换 |
| 示例模型 | 只有示例结构 | 用于体验，不能当作真实查询结果 |
| 模型快照 / 离线模型快照 | 本机保存的历史结构，不代表引擎仍在线 | 打开对应报表并重新连接后再实跑 |

Desktop 的端口会随重新打开而变化。助手会按保存的引擎身份、报表名称和可取得的文件路径寻找原报表，并重新核对实际结构。匹配唯一、结构一致时，原会话恢复在线，语义词典、历史和草稿保留；更换引擎会清理旧取值缓存。旧快照没有报表身份时，不会仅按相似结构猜测另一个端口。

页面每 3 秒刷新当前及正在生成会话的状态，后端正常时约每 20 秒做一次真实核对。临时失败先短暂重试三次，仍失败后以 2、5、10、20、30 秒退避继续检查；已有查询占用 Desktop 时，后台检查会让出资源。恢复不调用大模型、不修改报表。界面暂时连接不到本地 HTTP 服务时，不会直接认定 Desktop 已断开。

旧会话发送、验证或写入前仍会重新读取模型。数据分析的只读查询因可识别的连接断开发生失败时，最多自动重连后重试一次；语法错误和普通查询超时不走连接重试。已经结束的聊天请求以及模型写入不会自动重放，不能凭旧“通过”标签认定现在仍然有效。

### 何时使用“同步模型”

在 Desktop 中增加、删除或重命名表字段，调整关系、公式、描述，或应用了 Power Query 更改后，应点击右侧“同步模型”。

同步会读取新的模型快照，并自动开启新对话；旧对话仍可查看和导出。同一报表端口改变但结构未变时会自动恢复；结构已变时需要同步。无法唯一识别报表时，通过“连接 Power BI”手动重新扫描和选择。

不同工作空间和历史会话可能绑定不同快照。切换页面后，先看该页面显示的模型名称，不要假定所有页面都已同时切换到最新报表。

## 整理模型语义层

语义层是本机的业务字典，帮助助手分清“字段叫什么”和“业务上是什么意思”。**真实模型的 DAX 生成与数据分析需要先完成语义梳理；Power Query 模式没有此生成前置要求。**

### 首次梳理

1. 连接真实模型，点击右侧“模型语义层”。
2. 确认当前报表身份和界面注明的 AI 服务。
3. 阅读发送范围：点击“开始梳理模型语义”会把模型结构、公式和描述发送给该服务解释。
4. 等待分批处理，观察“已梳理 X/Y 项”和用户确认数量。
5. 梳理完成后，搜索本次任务涉及的关键字段与指标，逐条审阅。

梳理失败或超时不会丢弃已完成批次；处理好服务问题后点击“继续梳理”。完成后可使用“重新梳理候选含义”重新请求候选解释；这会调用模型服务，不能替代人工确认。

如果不希望用 AI 自动解释，也可以逐条手动填写并确认全部定义，完成本地词典。

### 审阅和确认业务定义

每个条目会显示以下状态之一：

| 状态 | 含义 |
| --- | --- |
| 业务含义未知 | 暂无充分定义，不能仅按名称推断 |
| 候选含义 · 待确认 | 有候选解释，但尚未获得用户确认 |
| 用户已确认 | 用户明确确认的业务定义 |

“已梳理完成”表示词典覆盖完成，**不等于所有业务定义已经确认**。

点击“编辑与确认”，可以维护：

- 业务名称；
- 业务含义与口径；
- 字段角色，例如业务日期、成本中心编号；
- 单位 / 币种，不确定时留空；
- 业务别名，用逗号分隔，供后续自然语言需求引用。

点击“保存为待确认”只保存候选；确认无误后再点击“确认业务定义”。可以展开“模型事实与依据”检查数据类型、显示格式、源字段、表达式、关系和已有描述，并用“只看待确认项”缩小审阅范围。

词典编辑保存在助手本地，不会改写 Desktop 中的字段名称或模型描述。编号筛选的单轮确认与全局业务词典不是一回事，不应把一次查询条件当作永久定义。

### 处理编号和歧义

例如业务编号 `0257`：

- 应按文本保留前导零，不要改成数值 `257`。
- 助手会根据需要执行本机精确取值检查，而不只根据字段名猜测。
- 只询问“0257 属于哪个字段”时，可直接解释实际匹配及来源，不一定出现筛选确认卡。
- 生成或分析时，完整检查范围内只有一个匹配字段，可以作为本轮建议口径，但不会自动变成用户确认。
- 出现重号、查值不完整或与已说明的业务含义冲突时，应按提示明确选择字段或补充定义。

知道字段时，直接点击右侧插入完整引用，并说明用途，例如：“使用 `'成本中心'[编号]`，按文本值 `0257` 筛选，不使用其他编号列。”

### 重开报表与复用词典

同一报表重新连接时，程序按报表名称、可识别的路径及模型结构匹配词典，而不是依赖旧 PID 或端口。未变化的定义和别名会保留；结构变化时只需处理新增或受影响的对象。

如果是旧版无报表名的词典、报表重命名或另存为，自动匹配可能不明确。出现“关联已有词典（模型结构相同）”时：

1. 核对候选词典的报表名称、路径和覆盖数量。
2. 选择确实属于同一业务模型的词典。
3. 点击“关联并复用”。
4. 再检查关键定义，不要因为结构相同就认定业务含义一定相同。

关联只读取本机记录，不重新调用 AI。词典复用不会把旧字段取值或旧分析数字当作当前结果；实际数据仍需重新查询。无标题报表不按通用名称自动匹配，建议先保存为有明确名称的报表。

## 查看字段实际取值

### 打开、搜索和返回

1. 在右侧“结构”页展开表。
2. 点击列旁的眼睛图标，而不是字段名称。
3. 查看总行数、不同取值数、空值统计、常见样例以及去重值对应的出现行数和比例。
4. 在预览中输入搜索内容，检查实际值是否存在；清空搜索可恢复默认列表。

也可以从业务字典点击“查看实际取值”，或从聊天的字段检查依据进入预览。从字典进入时，“返回业务字典”、右上角关闭或 Esc 都会先返回原字典，保留搜索、筛选和滚动位置；直接从模型面板进入则关闭后回到工作区。

### 正确理解预览

- 默认最多显示 50 个去重值，按出现次数排序，不是整列导出。
- 搜索针对模型真实去重值，统计卡片和常见样例仍是全模型范围。
- 预览不应用报表当前页面的筛选，范围是当前连接用户可读取的整个模型。
- 搜索无匹配不等于该字段没有数据；读取错误也不等于没有数据。
- “已截断”表示取值数量、字符长度或结果大小受到限制，不能把所见列表当作全部分类。
- 空值按模型 `BLANK()` 统计；可识别的空字符串另行统计，导入时已经转为空值的原字符串不能被还原。
- 手动预览只在本机查询，不调用 AI，不写入或刷新模型。有限取值与统计会在本机留存，但普通预览不是一条聊天记录。

## 使用 DAX 助手

### 生成、解释和优化

1. 连接目标模型；真实模型先完成语义梳理。
2. 选择左侧“DAX 助手”。
3. 在需求中说明指标、计算方式、筛选范围、时间粒度、单位和异常值处理。
4. 使用右侧字段或度量值按钮插入引用，减少名称错误。
5. 如有已知正确数值，先配置校准。
6. 发送后等待回复与验证完成，不要只看到代码就立即使用。

以下提示仅为格式示例，名称须替换为模型中的真实对象：

```text
请基于 '销售明细'[销售额] 和 '销售明细'[成本]，
生成毛利额与毛利率两个度量值。
毛利率 = 毛利额 / 销售额，销售额为 0 或空时返回 BLANK()。
不要额外限定年份、地区或客户，保持报表筛选上下文生效。
请先给基础度量，再给最终的毛利率，并解释单位。
```

解释公式时可以要求：“先解释变量、行上下文和筛选上下文，不改写代码。”优化时可以要求：“保持业务口径和空值行为不变，说明每项修改的原因。”

### 看懂验证结果

| 结果卡状态 | 可以说明什么 | 不能说明什么 |
| --- | --- | --- |
| 静态检查通过 · 未实跑 | 已通过程序可执行的静态引用等检查 | 不代表真实引擎能执行，也不能据此写入 |
| Desktop 实跑通过 | 已在本机引擎通过当前验证；存在校准时还需匹配校准结果 | 不代表所有时间、分组和业务场景都正确，也不等于性能全面达标 |
| Desktop 实跑未通过 / 验证未通过 | 存在引用、执行或校准问题，查看错误明细 | 不能忽略错误继续受控写入 |

验证本身使用临时查询，不会创建模型对象。验证失败时最多自动修复两轮；原始回复保留，修订追加在“验证修订 · 第 N 轮”下面。当前结果以最后一版候选代码为准，不要误用前面失败版本。

历史结果卡的“重新实跑本组代码”会验证同一回复中的基础与派生度量，不需要重新请求 AI，也不写入模型。若依赖度量既不在本组代码中，也尚未写入实际模型，会显示真实的缺失引用错误。

### 用已知结果校准

校准用于检验特定业务切片，不是让 AI 把输出数值硬改成目标值。它是**多个等值条件同时满足（且）+ 一个已知正确结果**。

1. 保持实时 Desktop 连接，点击输入框上方“校准”。
2. 点击“添加筛选条件”，依次选择表、字段、值类型并填写值。
3. 根据需要继续添加，最多 10 个条件。
4. 填写“已知正确结果”和“允许的绝对误差”。
5. 点击“应用到后续生成”，再发送 DAX 需求。
6. 生成后在校准结果中核对期望值、实际值及是否匹配。

例如，希望最后一个生成的度量计算“2025 年华东销售额”：

| 配置项 | 示例 |
| --- | --- |
| 条件 1 | 表“日期”，字段“年份”，值类型“数值”，值 `2025` |
| 条件 2 | 表“客户”，字段“地区”，值类型“文本 / 日期”，值 `华东` |
| 已知正确结果 | `123456.78`，仅为示例，请填真实且同口径的结果 |
| 允许的绝对误差 | `0.01` |

匹配规则为 `|实际值 - 期望值| <= 允许的绝对误差`。误差是绝对值，不是百分比；期望值应按底层数值填写。例如实际结果 `0.25` 对应显示为 25% 时，应填 `0.25`，不是 `25`。

其他注意事项：

- 不添加筛选条件时，校准整个模型范围的结果；不会继承报表页筛选。
- 日期使用 ISO 格式，例如 `2025-01-01`；布尔值填 `true` 或 `false`；空值选择“空值”类型。
- 编号 `0257` 应选文本类型，避免丢失前导零。
- 同一轮只配置一个期望结果；不是十个条件各自对应十个结果，也不支持在此界面配置“或”条件或范围运算符。
- 校准针对回复中最后一个度量值，可以依赖前面的基础度量；不用于 M 脚本或计算表。
- 点击“应用到后续生成”不会立即重算旧回复。改动条件后应重新生成；不再需要时点击“清除校准”。
- 条件属于当前工作区会话状态，新建对话应重新检查设置，不要假定自动继承。

### 审阅并写入模型

正式报表建议先“另存为”副本进行试用。当前项目验证记录尚未完成真实业务模型写入测试，不能把自动化替身测试等同于你的报表已验证可写。

1. 等待代码结果卡显示“Desktop 实跑通过”。
2. 点击“审阅并写入模型”。
3. 核对对象名称、度量值存放表、表达式和预期业务影响。
4. 如果确实要替换同名度量值，显式勾选“如果存在同名度量值，允许覆盖”；不勾选时不会擅自覆盖。
5. 点击“确认写入”。程序会重新读取模型，检查结构变化，再次验证后才尝试写入。
6. 回到 Desktop 检查新增或修改对象、关联视觉对象与结果。
7. 在 Desktop 按 Ctrl+S 保存报表文件。

写入不是把整段对话一次性应用：

- 每张结果卡对应一个对象；依赖基础度量时，先写入并核对基础度量，再处理派生度量。写入前单对象验证仍可能发现缺失依赖。
- 计算表只支持新建，不能覆盖同名已有表。
- 首次写入可能从官方 NuGet 下载固定版本 TOM 组件；网络或代理阻止时应让管理员检查访问条件。
- 写入后若提示“模型上下文同步失败”，对象可能已经写入，应先在 Desktop 核对，再同步模型，避免重复操作。
- 删除会话不会撤销已写入的对象。需要恢复时，在 Desktop 中恢复原公式或使用事先备份的报表。
- 助手写入内存模型不等于 PBIX 文件已经保存，必须在 Desktop 中保存。

## 使用 Power Query 助手

### 选择现有查询

1. 连接包含可读取 M 查询的模型。
2. 点击左侧“Power Query”。
3. 在输入框下方的目标查询下拉框选择要修改的查询。
4. 或者打开右侧“查询”页，点击查询查看代码，再点击“在清洗助手中使用”。

已有会话中更换目标查询会开启新对话，避免把一个查询的历史需求误用到另一个查询。模型没有可用查询时，不能直接发送此模式的请求。

### 生成与人工应用

需求示例：

```text
请基于当前查询生成完整 M 脚本，保留原始数据源和连接方式。
将“客户名称”去除首尾空格，将“订单日期”转换为日期类型；
转换失败的行请明确说明处理方式，不要悄悄删除。
说明每个步骤对行数和空值的影响。
```

操作顺序：

1. 说明需要保留的源步骤、列、数据类型和错误处理方式。
2. 查看生成的完整脚本及静态检查结果。
3. 点击代码块“复制”。
4. 在 Desktop 中打开“转换数据”，选中同名查询，再进入“高级编辑器”。
5. 先备份原 M 脚本，再粘贴新代码；核对数据源路径、凭据需求和转换步骤。
6. 在 Power Query 中检查预览、错误、行数和类型，再执行“关闭并应用”。
7. 应用完成后，在 Desktop 检查模型并保存；回助手同步模型后再继续。

**M 的静态检查不等于数据源访问或真实刷新验证。**助手不会自动执行外部 M 写回、刷新或绕过数据源权限；实际读取和应用发生在 Desktop 中。

## 使用数据分析助手

### 描述完整分析需求

1. 连接真实 Desktop 模型，完成语义梳理并确认关键指标。
2. 点击左侧“数据分析助手”。
3. 明确指标、时间范围、分组、筛选、比较对象和单位。
4. 指定使用模型中已有的度量值，避免名称相近却口径不同。

示例：

```text
使用现有度量值 [总销售额]，分析 2025 年每月销售趋势。
按 '日期'[月份] 分组，同时保留年份条件。
再按 '产品'[类别] 分析全年贡献。
请明确单位；如计算占比，单独查询同一筛选范围的总额作为分母，
不要用 TopN 样本之和代替总体，并给出实际查询来源。
```

每轮会重新规划、查询当前数据，再形成分析，不把旧回复中的数字当作本轮新取数。此流程不自动新建度量值，也不创建报表视觉对象。

### 回答口径确认问题

关键定义不充分时，界面会先显示确认卡，而不是立即做数值分析：

1. 阅读当前问题和候选项中的具体含义与字段依据。
2. 选择适用口径，可补充说明；也可使用自定义口径，只填写自己的定义。
3. 点击“确认并继续”。
4. 若还有缺失信息，继续回答下一项，或直接在聊天框补充。

每轮通常只确认一个问题，提供 2～4 个候选口径及自定义入口，不会默认替你勾选。已答卡片只读，只能提交当前最新问题；已明确的信息会沿用，无需重复选择。

有时分析前会先做只读字段取值检查，以确认“人员费用”等业务词实际对应什么分类。**查字段取值不等于已按某个口径执行金额分析**；确认有歧义的口径后才继续分析查询。

### 查看查询、结果和来源

回复下方的依据卡可展开：

| 标识 | 内容 | 应检查什么 |
| --- | --- | --- |
| `[F1]` 等 | 字段取值检查、匹配值、样例、空值统计、时间与查询依据 | 分类值是否真实存在，范围是否完整，是否有错误或截断 |
| `[Q1]` 等 | 本轮分析 DAX、状态、耗时、结果表和失败重试记录 | 指标、日期、筛选和分组是否符合需求，结论是否引用了正确结果 |

查询成功但没有匹配行，不代表金额等指标一定为零。查询全部失败时，助手会说明失败并停止数值分析；不要让没有成功结果支撑的文字充当业务结论。

查询成功后若模型未返回结论正文，助手最多复用同一份查询结果与图片重试一次，不会再次查询 Desktop；支持思考开关的接口会在这次重试中临时请求标准回复，原配置保留。重试仍受整轮总时限约束。若已有部分正文后被长度限制或中断，会保留文字并提示原因，不自动替换回复。请求的结束原因、token 用量（服务端有提供时）及请求 ID 会记录在本机，便于排查；不会显示或保存思考正文。

每轮最多四条分析查询，每条失败可修复一次。每个结果最多保留 200 行、30 列及约 24 KB 数据，界面表格预览前 20 行。自动字段检查不设固定字段项数上限，但最多执行两轮取值与规划，仍受整轮时限约束；单项最多保留 20 个去重值及约 6 KB 取值数据。

### 下载 CSV 与继续追问

展开成功查询，点击“下载本次结果 CSV”。下载包含**本次已保留**的结果，不只前 20 行；但如果标注“已截断”，CSV 同样不是完整数据。

需要更多数据时，应缩小范围、按期间分批查询，或让助手在模型中聚合。不能把 TopN、样例或截断数据当作总体计算占比、总额和覆盖率。

可以继续追问：“在相同时间和口径下，只看华东地区，并按产品类别重新查询。”仍应核对新一轮来源；每轮均可能调用 AI 并执行真实只读查询。

## 使用图片与截图

三种助手都支持图片，适合提供错误提示、界面截图、业务口径说明或公式截图。

### 添加图片

- 点击输入框上方“＋ 图片”，选择 PNG、JPEG 或 WebP 文件。
- 将图片拖入输入框。
- 截图后聚焦输入框，按 Ctrl+V 粘贴。
- 点击“截图”打开 Windows 截图工具，完成框选后**回到输入框按 Ctrl+V**；点击按钮不等于已经自动附图。

添加后会显示缩略图，可点击查看或移除。等待上传完成后，输入需求再发送，也可以仅发送图片。

### 图片限制与保存方式

- 每条消息最多 4 张，每张原文件不超过 8 MB；不支持 SVG、PDF 等作为图片附件。
- 本机会校验真实图片、去除附加元数据，长边缩到最多 2048 像素，转换为最多 2 MB 的 PNG/JPEG。
- 小字截图经过压缩后可能不够清晰；建议裁剪关键区域，同时粘贴可复制的错误文字或代码。
- 添加图片只上传到本机；发送消息时，真实图片内容才随对话发送给所选模型服务。
- 后续请求会携带近期附图，每次请求最多 8 张历史与本轮图片；较早图片超出预算时会注明未重发，需要时重新附上。
- 模型不支持图片时会明确报错，不会悄悄忽略附件。改用视觉模型，或移除图片并改发文字。
- 未发送图片草稿只在当前运行期间保留；移除会删除暂存，超过两天的未发送暂存图在启动时清理。
- 已发送图片随消息保存到本机数据库，重启后可查看，删除会话时一起删除。

截图中的数值只是用户提供的线索，不能代替数据分析模式的本轮真实查询证据。发送前检查截图是否包含个人信息、密钥或不允许交给模型服务的业务数据。

## 管理对话与后台任务

### 新建、切换和查找

- 点击“新建对话”或 Ctrl+K，适合新任务、不同业务口径或同步后的模型。
- 切换三种工作空间时，原页面的输入草稿、查询选择、校准条件和未提交确认选项分别保留，不会混到别的会话。
- “最近对话”当前最多加载 300 条记录，搜索只按该列表的标题过滤，不是所有历史正文检索。
- 点击某条历史记录会恢复对应助手、模型快照、消息和已保存结果；继续实跑前仍需要真实 Desktop 可用。
- 未发送草稿不是持久化会话内容，退出前应自行保存重要草稿。

### 生成期间做其他工作

生成中可以切换助手、查看历史或新建其他会话，原任务继续在后台运行。不同会话可以独立生成，但同一会话必须等待当前请求完成才能再次发送。

发送按钮旁有独立的“中止”按钮，当前会话生成时可点击；原发送按钮保持不变。中止后，本轮不再继续生成、查询、修复或总结，已收到的文字、完成的查询结果和已发送图片保留，并标记“已中止”。等待按钮恢复后，可继续发消息。切到其他正在生成的会话后，中止只作用于该会话；切换页面仍保持后台生成。尚未提交到后端的消息中止时，会恢复输入和图片草稿。

中止会关闭当前模型响应连接，并向正在执行的 Desktop 只读查询请求取消；实际引擎响应和模型服务器资源回收由相应服务处理。它不会删除历史，也不会撤销之前确认写入 Desktop 的内容。

侧边栏显示“生成中”，切换后顶部出现后台任务入口；完成后会提示，未查看结果显示“已完成”或错误状态。点击任务即可返回，不必重复提交。

页面刷新或显示连接暂时断开时，只要本地后端仍在运行，生成可能仍在继续，重新打开会话可恢复查看。关闭整个桌面应用则会停止本地服务，不能当作“最小化到后台”。

超时或中断后，已经收到的文字、修订内容和已执行分析查询结果会保留；重新进入会话先查看现有内容，再决定是否重试，避免重复消耗模型调用。

### 导出与删除

**导出：**

1. 打开已有会话。
2. 点击对话顶部“导出对话”下载图标。
3. 保存 Markdown 文件。

导出包含会话文字、代码原文、修订内容、验证通过/实跑标记、字段检查和已保留分析结果；图片以数据形式内嵌，不依赖助手运行。查看内嵌图片需使用支持该方式的 Markdown 阅读器。Markdown 与 CSV 是阅读或交换结果的文件，不是可重新导入的完整工作区备份。

**删除：**

点击历史记录旁的删除图标，核对确认弹窗后删除。生成中的会话需等完成后才能删除。此操作会删除本机会话及关联记录、图片、分析结果；不会删除已经下载的文件，也不会撤销 Desktop 中已写入的内容。重要结果应先导出或备份。

## 本地存储、备份与数据流向

### 数据在哪里

| 运行方式 | 默认用户数据目录 |
| --- | --- |
| 正式安装版 | `%LOCALAPPDATA%\PowerBIAssistant` |
| 源码运行版 | 项目根目录下的 `data` |
| 自定义位置 | 启动前设置的 `PBI_DATA_DIR` 指向目录 |

安装版的用户数据目录和 `%LOCALAPPDATA%\Programs\PowerBIAssistant` 程序目录是两个不同位置。

主要数据文件：

| 文件 | 用途 |
| --- | --- |
| `assistant.sqlite3` | 会话、图片、模型配置与快照、语义词典、查询结果、验证和写入审计等 |
| `secret.key` | 解密本地保存 API Key 所需的密钥，需和数据库一起备份 |
| `assistant.log` | 运行与启动错误日志，排查问题时使用 |

API Key 在本地加密保存，但**不是整个数据库都已加密**。会话、图片和业务结果同样需要用 Windows 账户权限、磁盘保护和公司数据管理规范保护。把数据库与密钥一起交给他人可能暴露凭据和业务内容。

### 备份与恢复

1. 等待需要保留的任务结束，关闭助手；浏览器预览还需停止对应终端服务。
2. 备份完整用户数据目录，尤其同时保留 `assistant.sqlite3` 和 `secret.key`。
3. 将备份保存到有访问控制的位置，不上传公开仓库。
4. 恢复前先关闭目标助手，并备份目标目录中的现有数据。
5. 将备份放回实际使用的数据目录，再启动软件。
6. 检查模型配置、历史与词典；打开 Desktop 报表并重新连接，核对当前模型结构。

备份助手数据不等于备份 PBIX 文件，报表文件应单独备份。跨电脑迁移还需满足新机器的授权要求、Desktop 环境、模型服务网络与凭据权限。

设置 `PBI_DATA_DIR` 只改变存储位置，不会自动搬运旧数据；启动后发现“历史不见了”时先检查目录是否改变。卸载安装版不会删除用户数据，但卸载前仍建议备份。

### 哪些内容会发送到模型服务

| 操作 | 本机行为 | 发送到所选模型服务的内容 |
| --- | --- | --- |
| 连接模型、手动预览字段、关联历史词典 | 读取 Desktop 或本机记录 | 这些操作本身不调用 AI |
| 开始语义梳理 | 读取并整理模型元数据 | 模型结构、公式和描述等解释所需内容 |
| DAX / Power Query 对话 | 使用当前模型上下文，执行相应检查 | 相关模型结构、M 查询、对话和已发送图片等 |
| DAX 自动修复 | 本机实跑、校准 | 修复所需的验证错误、校准差异及相关证据 |
| 数据分析 | 本机执行只读 DAX 与字段检查 | 规划、修复和总结所需的本轮保留查询结果、相关字段值与统计等 |
| 重新实跑本组代码 | 本机临时查询，不写入模型 | 此按钮本身不重新调用 AI |
| 审阅确认写入 | 本机重新验证并写入 | 写入操作本身不需要 AI，首次可能下载官方引擎组件 |

程序不上传 PBIX 文件，但“文件没上传”**不等于“业务数据不出本机”**。模型服务仍会接收任务所需内容，可能包括数据源信息、实际值、公式和截图。只配置经授权可处理这些信息的服务；不要在需求、截图、M 代码或问题反馈中暴露不必要的密钥。

## 常见问题与处理方法

| 现象 | 优先检查与处理 |
| --- | --- |
| 启动提示授权验证失败 | 核对是否使用本机机器码对应的 CD-KEY，程序旁授权是否缺失；更换机器或重装系统后联系发布者重新发码，查看用户数据目录日志 |
| 桌面窗口无法打开或空白 | 检查 WebView2 Runtime；源码版确认依赖已安装，查看 `assistant.log`。开发排查可用浏览器预览区分窗口与后端问题 |
| 双击 `start.bat` 失败 | 确认项目根目录已有 `.venv` 且装了 `requirements-desktop.txt`；按源码启动步骤在 PowerShell 查看错误 |
| 找不到 Power BI 实例 | 确认在本机 Desktop 已打开含模型的报表并完成加载，再“重新扫描”；不是只打开浏览器中的 Power BI 网页 |
| 列出了多个实例，不确定选哪个 | 核对报表名和路径；连接后再检查右侧字段，不以端口号作为报表身份 |
| 自动重连中 / 等待 Desktop | 保持对应报表打开并等待恢复；名称或路径无法识别、存在多个同名实例时手动重新扫描，不依赖历史快照继续运行 |
| 提示模型结构已变化 | 同步模型并在新对话继续；必要时审阅受影响的语义定义 |
| 发送后弹出语义层而未生成 | 真实模型的 DAX/分析需完成语义覆盖；完成或继续梳理后再发送 |
| 同一报表又要求梳理词典 | 检查名称、路径、结构是否变化；存在候选时使用“关联已有词典”，不要盲目复用不同业务报表 |
| 模型测试出现 401 / 403 | 检查该条目的 API Key、服务权限和协议；`local` 只适用于不要求真实鉴权的内部服务 |
| 模型测试出现 404 / 模型不存在 | 检查 API 根地址、协议及模型 ID；不要使用聊天网页 URL 或随意追加操作路径 |
| 一直等待或生成超时 | 查看是模型无新数据还是整轮时限到达；检查网络与服务负载，按需调整等待/总时限，不要仅因无正文就认为深度思考已停止 |
| 模型因长度限制停止 | 检查所选模型的“单次输出额度”；思考可能消耗额度，在模型支持范围内提高额度或缩小任务，已输出文字会保留 |
| 查询成功但结论仍为空 | 助手会复用结果重试一次；仍失败时查看结束原因、是否仅收到思考数据及模型服务状态，结果卡和 CSV 仍可查看 |
| 图片发送失败 | 检查格式、每张 8 MB 和每条 4 张限制，等待上传完成；确认所选模型支持视觉输入 |
| 点击截图却没出现附件 | 截图后回到输入框按 Ctrl+V；截图工具入口不自动把框选结果发送给 AI |
| 只有“静态检查通过”，没有写入按钮 | 可能使用示例模型，或尚未通过真实验证；连接实际 Desktop，在有效会话中重新实跑 |
| 实跑通过但业务数字不对 | 核对指标口径、关系、时间、筛选与单位；实跑只证明当前验证通过，增加同口径校准并检查其他切片 |
| 校准不匹配 | 检查条件是否应为“且”、字段值类型、前导零、日期格式、底层数值单位及目标是否为最后一个度量值 |
| 派生度量写入失败 | 检查依赖是否已存在于实际模型；组验证使用临时定义，不代表基础度量已持久写入 |
| 首次写入组件下载失败 | 检查对官方 NuGet 的网络和代理访问；不要从不可信站点随意下载 DLL 替换 |
| Power Query 显示没有可用查询 | 核对所连模型是否实际包含可读取 M 查询，确认目标查询并同步；不能凭空选择不存在的查询 |
| 字段预览与报表图表数字不同 | 预览是全模型范围，不继承当前页面筛选；明确需要的筛选，并注意空值与截断说明 |
| CSV 比预期少 | 区分界面前 20 行预览与最多保留 200 行结果；有截断时 CSV 也仅含保留部分，改用分批或聚合查询 |
| 切页后看不到刚才生成的回复 | 从后台任务入口或原历史会话返回，结果只更新所属会话 |
| 重装或切换启动方式后历史为空 | 检查当前数据目录、`PBI_DATA_DIR`、安装版与源码版的目录差异；先备份，再恢复到正确位置 |
| 删除会话后模型对象仍在 | 这是预期行为，历史删除不撤销模型写入，应在 Desktop 中处理 |

向维护人员反馈问题时，建议提供：运行方式、错误出现时间、所在助手、复现步骤、完整错误文字、相关日志片段，以及是否使用真实 Desktop 模型。日志、截图和模型名称可能包含敏感信息，发送前先脱敏；不要提供 API Key、`secret.key` 或整份业务数据库。

## 限制速查与交付前检查

### 常用限制

| 项目 | 当前规则 |
| --- | --- |
| 同一会话请求 | 当前生成完成后才能再次发送 |
| DAX 自动修复 | 最多两轮 |
| 校准 | 最多 10 个同时满足的条件、1 个期望结果；针对最后一个度量值 |
| 手动字段预览 | 默认最多 50 个去重值，超限显示截断 |
| 编号精确查值 | 最多检查 96 个文本或未知类型字段；单命令最多 5 秒，单编号约 15 秒，未完成会注明 |
| 每轮分析查询 | 最多 4 条，每条失败可修复 1 次 |
| 分析结果 | 界面预览前 20 行；每个结果最多保留 200 行、30 列及约 24 KB |
| 分析字段检查 | 最多两轮取值与规划，不设固定字段项数上限；单项最多 20 个值及约 6 KB |
| 单条分析引擎查询 | 60 秒命令超时，整轮另受模型服务总时限约束 |
| 图片输入 | 每条最多 4 张，原图每张不超过 8 MB；PNG/JPEG/WebP |
| 图片历史上下文 | 每次模型请求最多 8 张近期历史与本轮图片 |
| 无新数据等待 | 默认 90 秒，可设 30～600 秒 |
| 生成总时限 | 默认 900 秒，可设 180～7200 秒 |

### 把结果交付他人前

- 确认连接的是正确报表，不是示例或离线快照。
- 确认业务字段、指标、时间范围、币种和单位已说明，没有把候选语义当作事实。
- 对关键 DAX 核对实跑和校准结果，并覆盖必要的其他业务切片。
- 对分析核对 `[Qn]` 来源，排除把空结果认作零、把 TopN 或截断样本认作总体的情况。
- 对 M 脚本在 Desktop 中实际应用并验证，而不只依赖静态检查。
- 写入后在 Desktop 核对并保存，重要报表保留修改前副本。
- 导出时确认 Markdown/CSV 的数据范围和敏感信息；需要恢复工作区时另做完整数据备份。
